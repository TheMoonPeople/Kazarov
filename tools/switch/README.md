# Nintendo Switch support

Kazarov owns the libnx platform layer, Mesa/NVK and SDL toolchain, compatibility headers, native ZIP reader, and SDK validation harness used by its games. Consumers supply their title metadata, icon, data installation instructions, and game-specific entry adapters.

Include `cmake/KazarovSwitch.cmake` before creating the host library, then call `kz_switch_host(host_target)`, `kz_switch_runtime(runtime_target)`, and `kz_switch_nro(executable_target NAME ... AUTHOR ... ICON ...)`. The consumer's Switch preset uses devkitPro's `Switch.cmake` toolchain. `KZ_SWITCH_APPLICATION_NAME`, `KZ_SWITCH_LOG_FILE`, and `KZ_SWITCH_DATA_INSTRUCTIONS` configure the shared startup and missing-data screen.

Run `tools/kazarov/tools/switch/build.sh` from the game checkout, or set `KZ_SWITCH_ROOT` to that checkout. The shared image builds pinned Mesa 26.2.4 NVK, Vulkan-capable SDL3, host shader tools, libiconv 1.18 for CP932 text, and Kazarov's minimal LGPL-only FFmpeg 9.0.2 under `/opt/switch/ffmpeg`. The FFmpeg importer requires its build stamp on Switch and rejects GPL, nonfree and version-3-only configurations. `KZ_SWITCH_IMAGE` selects an existing compatible image for local validation; otherwise the build hashes the toolchain inputs and rebuilds the image when they change. `BUILDER`, `JOBS`, and `CLEAN` retain their build-script meanings. On Windows, invoke `tools/kazarov/tools/switch/build.ps1 -Root <game checkout> switch`.

`JOBS` defaults to four and must be a positive integer. It also sets the image's `BUILD_JOBS` argument, bounding its Mesa, CMake, Cargo, libiconv and FFmpeg builds. Game builds inherit this limit through `CMAKE_BUILD_PARALLEL_LEVEL` and `CARGO_BUILD_JOBS`; explicitly supplied values for those variables take precedence.

The shared startup mounts embedded romfs, composes Homebrew Menu arguments with whitespace-separated `args.txt`, and accepts `--env NAME=VALUE` entries there. It enables the accepted display-list arena, conservative alpha/fog specializations, combined depth planes, reciprocal near-fog calculation, and inline render dispatch. Game-specific shadow and haze settings belong to the consumer. Experimental shader and fused-2D paths remain disabled.

Outside nxlink sessions, stdout and stderr reach Horizon's system log manager. Homebrew Menu launches also write a bounded 4 MiB application log through a low-priority writer; installed NSP applications avoid SD log writes. `SwitchUpdateDisplay()` applies docking changes outside an active frame. The Quill portability hook retains its double-sized queue storage with aligned heap allocations, obtains Horizon thread IDs and CPU masks, and normalizes UTC timestamps without a process-wide timezone change.

The log sink remains explicitly owned through C++ static destruction. A cleanup callback registered during `userAppInit` drains and joins its file writer before newlib closes standard I/O; `userAppExit` provides an idempotent fallback. Shutdown detaches new writes under a lifetime mutex, closes the file, and then destroys the sink. A launch that never opened a sink is safe. If the callback cannot be registered, the optional file writer stays disabled while system logging remains available.

The selected FFmpeg include prefix takes precedence over devkitPro's broad system include root. This keeps the headers and static libraries from the same package; devkitPro's portlibs may provide another, ABI-incompatible FFmpeg version. The header-precedence regression test deliberately places incompatible headers in that system root.

The exit runtime dynamically extends newlib's callback tables beyond 32 entries while retaining its `atexit`, `on_exit`, `__cxa_atexit` and `__cxa_finalize` wrappers. Both registry and dispatch use the same newlib ABI and recursive lock; callbacks run without the lock and may register further callbacks or finalize another DSO. Reused slots clear their signature and DSO metadata. This covers a toolchain whose headers enable dynamic allocation while its shipped registry and dispatcher omit it: upstream gates extension on both `_ATEXIT_DYNAMIC_ALLOC` and `MALLOC_PROVIDED`. See newlib's [registration source](https://github.com/devkitPro/newlib/blob/master/newlib/libc/stdlib/__atexit.c) and [dispatch source](https://github.com/devkitPro/newlib/blob/master/newlib/libc/stdlib/__call_atexit.c).

`devkit-run.ps1` packages a libnx ELF as an SDK application for an explicitly named development unit. It accepts a unique `ProgramId`, application name, raw argument string and `RomfsFiles` mapping, and records ELF/NSO hashes, launch output, target logs, final screenshot, and run status in an isolated directory. Use `-Nso path/to/code/main` instead of `-Elf` to reuse an already converted NSO without Docker; the manifest records the input kind, source path and NSO hash without inventing ELF provenance. `StageOnly` performs offline staging. Runs hold the existing `chronicle-edev.lock`, terminate the application and restore automatic operation/performance policies during cleanup. A duration-limited smoke run records `timed_out`; a run with `CompletePattern` records `completed` only after that pattern appears. The harness does not select scenes or save paths.

`run.sh` sends an existing NRO through nxlink. Set `SWITCH_NRO` and `SWITCH_INSTALL_PATH` in the consumer wrapper and `SWITCH_ADDRESS` when broadcast discovery is unavailable.

The native archive regression suite requires a C++26 compiler, Python 3, zlib and libzstd development files. Configure `tools/switch/tests` as a standalone CMake project, build, and run CTest. The Python driver also accepts `--probe <built kazarov_archive_probe> --archive <data.zip>` for independent, reproducible samples from a local asset archive. Fixtures cover stored, deflate, Zstandard, empty files, UTF-8 paths, ZIP64 entry-count boundaries, CRC errors and malformed local headers; no game data is tracked.
